# 路线图与能力矩阵

## 分类

- 核心实现：第一阶段必须可用
- 架构预留：第一阶段建立边界、事件和接口
- 后续模块：需要时独立开发
- 独立系统：不能直接扩展，必须隔离

| 能力 | 分类 | 第一阶段动作 |
|---|---|---|
| 市场同步与标准化 | 核心实现 | Provider、原始表、统一模型 |
| 免费积分账本 | 核心实现 | 双重记账、幂等、冲正 |
| 报价和模拟预测 | 核心实现 | Quote、Prediction、Position |
| 结算 | 核心实现 | 状态机、证据、版本、重算 |
| 管理后台 | 核心实现 | 市场、结算、用户、审计 |
| 基础排行榜 | 核心实现 | 赛季周期与最低样本 |
| 多语言 | 架构预留 | 原文和翻译分离 |
| 多Provider | 架构预留 | MarketProvider接口 |
| 评论和动态 | 预留+后续 | 内容对象、审核、举报 |
| 好友/关注 | 预留+后续 | 独立关系模型 |
| 私人房间 | 预留+后续 | 房间、成员、角色、可见性 |
| 用户创建市场 | 预留+后续 | 来源、创建者、审核、规则版本 |
| 任务/成就 | 预留+后续 | 领域事件和奖励规则 |
| 赛季/团队 | 预留+后续 | 排行主体和周期通用化 |
| AI摘要 | 预留+后续 | 异步任务、版本、人工审核 |
| 会员权益 | 预留+后续 | Entitlement，不写死isPro |
| 移动App/Bot | 预留+后续客户端 | API优先 |
| B2B API | 预留+后续 | 鉴权、额度、审计 |
| 真实支付 | 独立系统 | 不进入娱乐平台账本 |
| 真钱下注/托管 | 独立受监管系统 | 独立法人、KYC/AML、资金隔离 |

## 里程碑

- M0工程基线：文档、Monorepo、CI、Docker、自检、数据模型。
- M1数据闭环：同步、标准化、价格快照、后台审核、只读展示。
- M2预测闭环：身份、免费积分、报价、预测、持仓、结算、流水。
- M3运营闭环：排行、每日奖励、通知、后台、风控、分析。
- M4游戏化：赛季、任务、成就、好友、房间、团队。
- M5平台化：多Provider、用户市场、AI、会员、B2B API、移动端。

每个里程碑必须通过测试、文档、监控和恢复演练，不以“页面能点”作为完成标准。
