# 开发、测试、发布与文档流程

> 文档版本：V0.2
> 最后更新：2026-07-30

## 1. 需求进入开发前

每项功能必须写清：用户问题、业务规则、不做什么、验收标准、影响模块、数据库变化、安全与滥用风险、监控指标和回滚方案。

## 2. 分支

禁止直接在`main`开发。使用`feature/...`、`fix/...`、`docs/...`或`agent/...`。

## 3. 工程切片与发布完成定义

功能 PR 只有同时满足以下条件才可以合并：代码完成、类型检查和关键测试通过、适用的权限与
幂等验证、必要日志指标、文档/Changelog/CURRENT_STATE/Issue 同步、回滚明确且不含秘密。
尚未建设的管理页面不能作为底层切片的虚假完成条件，但必须在路线图和已知限制中保留。

Staging 验收、备份恢复、真实网络长时间运行、容量压测、灰度和生产只读权限属于发布门槛。
基础设施切片可以在这些环境存在前通过 CI 合并，但不能因此宣称已经生产完成或可公开上线。

## 4. 数据库变更

- 只能通过迁移；
- 迁移向后兼容；
- 先加结构，再部署读取，再迁移数据，最后删除旧结构；
- 迁移前备份；
- 生产禁止直接改表；
- 账本记录禁止物理删除。

## 5. API

- 路径版本`/api/v1`；
- 请求带`request_id`；
- 写操作支持`idempotency_key`；
- 错误返回稳定错误码，不暴露堆栈；
- 前端不能直接访问数据库；
- Web、移动端和Bot复用API；
- 破坏性变化新增v2。

## 6. 测试层次

- 单元：价格、份额、结算、评分、权限、配置。
- 集成：事务、账本守恒、幂等、Outbox、迁移。
- 契约：Polymarket示例响应和标准化结果。
- 端到端：注册→积分→报价→预测→结算→流水→排行。
- 故障：API超时、WebSocket断线、Worker重启、重复消息、结算中断。

## 7. 发布

```text
功能分支 → Pull Request → CI → 合并
→ 部署 Staging → 自动/手工验收 → 数据库备份与恢复证据
→ 功能开关关闭 → 生产部署 → 健康检查 → 灰度打开 → 监控
```

严重异常：关闭功能、切只读、回滚应用、保存证据，不随意回滚已写数据，通过冲正与正式修复恢复。

## 8. ADR

涉及技术栈、数据模型、账本、结算、消息系统或安全边界的决定，在`docs/adr`新增记录。ADR不删除；废弃时新增替代ADR。
